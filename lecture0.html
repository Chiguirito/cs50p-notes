    Return values: print vs return

    Mental model — the most important idea in this lecture

    print and return feel similar but do completely different things:

    print(x) → screenShows a value to a human. Your code can't catch it. The function still hands back None.
    return x → callerHands a value back to your code, so you can store and use it.

    Which statement is true?

    print is for showing things to a person. To use a result elsewhere in your program, the function must return it.

    Later

    There is a way to share variables across functions (global), but it's almost always better to return values and pass them as arguments. We'll lean on return.

    Readability wins

    Code is read far more often than it's written. Favour clear names and obvious steps over clever one-liners. The goal isn't to impress the computer — it's to be understood by the next person (often future-you).

    Common mistakes at a glance

    • input() always returns a str — wrap it in int()/float() to do math.
    • print shows a value; it returns None. Use return to hand a value back to your code.
    • Forgetting the f on an f-string prints {braces} literally — and gives no error.
    • Defining a function isn't calling it — calling needs the parentheses: main().
    • Call main() at the bottom; calling before a definition is a NameError.
    • int("3.5") raises ValueError; int(3.9) truncates to 3 (no rounding).
    • A variable made inside a function doesn't exist outside it (scope).
    • / always returns a float (6 / 2 is 3.0); use // for whole-number division.
